# DSL Architecture — 本地化DSL设计框架

> 熵减 Agent 生态的本地化DSL+LSP架构

## 核心定位

**先做「带标准野心的工具」，而非直接做标准**
- 标准在没有大规模采用前是死的
- 工具的 AST Schema + 模块契约天然成为事实标准
- 硬约束：不碰运行时、不碰模型层，只做**静态语义基础设施**

**核心指标**：复用发现时间 < 3秒

---

## 一、DSL 设计哲学：80/20法则

| 成分 | 比例 | 职责 |
|------|------|------|
| 声明式 | 80% | 描述「做什么」— 任务拓扑、工具契约、记忆策略、输入输出schema |
| 命令式逃生舱 | 20% | 轻量级逻辑表达式（`when: len(results) > 3`），禁止函数/类/模块定义 |

### 设计原则
- **人类可读优先**：复用的前提是「人能快速判断这个模式是否匹配我的需求」
- **机器可解析是底线**：不能为了可读性牺牲解析能力
- 白名单语法：不是「除了X都可以」，而是「只允许这些」

### 示例语法
```hcl
workflow "research" {
  step "search" {
    tool = "web_search"
    input  = query
    output = raw_results
  }
  step "decide" {
    type = "gate"
    condition = "len(raw_results) > 0"
    then  = "synthesize"
    else  = "fallback"
  }
}
```

## 二、AST 层级：停在「意图层」

**关键判断**：抽象到「任务拓扑 + 资源契约」这一层。

| 层级 | 示例 | 评价 |
|------|------|------|
| 太高 | `agent "x" { goal = "do research" }` | 玩具，失去工程价值 |
| **意图层（目标）** | `step "search" { tool = "web_search", input_schema = {...}, retry_policy = ... }` | ✅ 表达「做什么」和「依赖什么」，不规定「怎么实现」 |
| 实现层 | `requests.get(...)` | 太低，变成写代码，无法跨框架复用 |

### 意图层语义原语
- 任务拓扑（step 连接关系）
- 资源契约（输入输出 schema）
- 工具签名（tool name + 参数契约）
- 重试策略
- 记忆策略

## 三、语义哈希：分层指纹 + LSH

### 分层指纹
| 层级 | 内容 | 用途 |
|------|------|------|
| L0 | 拓扑（节点类型 + 连接关系，忽略标识符和值） | 粗筛，O(1)桶查找 |
| L1 | 拓扑 + 工具签名/schema | 模糊匹配 |
| L2 | 完整语义 | 精确匹配 |

### 归一化规则
- 变量名统一为 `VAR_1`
- 字面量按类型保留或泛化
- **工具名保留**（关键契约）

### 索引架构
```
LSH粗筛(O(1)) → 结构特征预过滤 → 树编辑距离精排
```
- 存储：本地SQLite（WAL模式 + 内存映射）
- 性能目标：10k节点规模，<3秒发现，误报率<5%

## 四、CEL 安全边界：三级函数体系

### 核心原则
**默认拒绝一切，显式授予能力**

每个表达式执行前必须持有「能力令牌」，由编译器静态检查，解释器强制执行。

| 等级 | 类别 | 示例 | 授予方式 |
|------|------|------|----------|
| L0 核心 | 纯数学/逻辑 | len, abs, contains, regex_match, format | 无需声明，始终可用 |
| L1 数据 | 只读数据访问 | env("KEY"), file_read, json_parse | 需声明 `capabilities = ["data:read"]` |
| L2 受限IO | 受控网络/文件 | http_get(url, timeout), cache_lookup | 需声明 + 参数必须是编译时常量 |
| L3 危险 | 任意执行 | exec, system, eval, import | **不存在此令牌，编译器直接拒绝** |

### 编译时常量约束
L2函数的URL/文件路径/超时时间**必须是编译时可求值的常量**。

### 控制机制
1. 编译时静态检查
2. 运行时能力列表（Capability List）
3. 审计日志

## 五、LSP：语义级复用发现引擎

不只是IDE补全，而是：
- 跨项目模式识别和推荐
- 代码片段/模式/模板的发现机制
- 本地符号索引 + 语义哈希联合查询

---

## 六、迁移路径

现有Agent项目（OpenHands、CAMEL等）接入：
- **反向解析**（decompilation）：原项目agent定义 → 中间AST → DSL
- **适配层**：渐进式接入，非强制迁移

## 七、待解决风险

| 问题 | 风险 | 状态 |
|------|------|------|
| CEL内置函数列表治理 | 危险函数注入导致安全模型失效 | 待定 |
| LSH在SQLite上的实际性能 | 向量空间索引性能未验证 | 待benchmark |
| 结构等价类边界定义 | 跨项目复用精度不稳定 | 需定义清晰边界 |
