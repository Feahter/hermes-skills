## 核心架构

### DSL 设计哲学
- **先做工具，工具带标准野心**：AST Schema + 模块契约天然成为事实标准
- **80/20法则**：80%声明式（做什么） + 20%命令式逃生舱
- **人类可读优先**：DSL 过度符号化会降低复用率
- **白名单语法**：`when: len(raw_results) > 0` 这种轻表达式是逃生舱上限

### AST 层级：意图层
- **不是纯玩具**（`goal = "do research"`）
- **不是写代码**（`requests.get(...)`）
- **意图层**：任务拓扑 + 资源契约 + 工具签名 + 输入输出 schema + 重试/记忆策略

### 语义哈希：分层指纹 + LSH
- L0 拓扑指纹（节点类型+连接关系）
- L1 契约指纹（L0 + 工具签名/schema）
- L2 完整指纹
- 归一化：变量名→VAR_1，工具名保留
- 查询：LSH粗筛 → 结构特征预过滤 → 树编辑距离精排

### CEL 安全模型
- **默认拒绝一切，显式授予能力**
- L0核心（纯数学/逻辑）：无需声明
- L1数据（只读访问）：需声明 `capabilities = ["data:read"]`
- L2受限IO（网络/文件）：需声明 + 参数必须是编译时常量
- L3危险（任意执行）：不存在此令牌，编译器直接拒绝

### LSP：语义级复用发现引擎
- 跨项目模式识别和推荐
- 代码片段/模式/模板发现
- 本地符号索引 + 语义哈希联合查询
