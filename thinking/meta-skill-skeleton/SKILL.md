# Meta-Skill Skeleton

*动态编译器——不是被动分配资源，而是主动修改自身结构的元认知系统*

---

## 一、SKILL.md 高影响字段（按重要性排序）

| 字段 | 作用 | 失败模式 |
|------|------|---------|
| `description` | 唯一决策依据，含触发词 | 只有"用于X"，无触发关键词 |
| **`反例/负面模式`** | 告诉AI何时失效 | 只写正面，不写"不用于Y" |
| **`输入输出契约`** | 清晰格式，消除散文输出 | 模糊导致理解分歧 |
| **`依赖声明`** | 前置skill/工具，显式声明 | 隐性依赖导致组合失败 |
| **`认知负荷预算`** | 何时拆子agent | 忽视导致上下文溢出 |
| **`版本兼容性`** | 工具版本差异 | 过时产生破坏性建议 |
| `Verification` | 验证执行正确性 | 质量不稳定 |

## 二、三层元认知框架（构建时必走）

### 第一层：元认知监控（Metacognitive Monitoring）
- **矛盾探测器**：强制找反例——"这个结论在___条件下失效？
- **表征转换**：同一问题用数学/视觉/叙事三种语言表达
- 触发词覆盖：description 是否覆盖了用户的真实触发语境？

### 第二层：自我调节（Self-Regulation）
- **分解/综合张力**：拆得完，能装回去吗？
- **抽象/具象张力**：说到概念，有没有一个具体的体感锚点？
- **负空间探测**：这个设计的"不存在的东西"是什么？

### 第三层：社会智能（Social Intelligence）
- **心智对齐**：skill是给人用的——写清楚"不擅XX场景"而非泛泛"通用"
- **动态能力映射**：sensing x seizing x transforming

## 三、Emergent Behavior 记录（组合涌现的核心）

**记录格式：**
```
### 涌现行为
- [日期] skillA + skillB → 效果描述
- 风险：skillA + skillC → 潜在问题
```

**5种用法：** 反脆弱测试 / 能力边界探测 / 高频组合压缩 / 故障归因 / 创新发现

---

## 四、Skill 创作 Checklist

- [ ] `description` 含触发词（自然语言测试P=1.0 R=1.0）
- [ ] 有明确的"不用于Y"反例
- [ ] 输入输出格式明确
- [ ] 依赖skill/工具已声明
- [ ] 有认知负荷预算（何时拆子agent）
- [ ] 有版本兼容性说明
- [ ] 有Pitfalls/禁忌
- [ ] 有Verification验证步骤
- [ ] 在道/法/术/器四层中有定位
